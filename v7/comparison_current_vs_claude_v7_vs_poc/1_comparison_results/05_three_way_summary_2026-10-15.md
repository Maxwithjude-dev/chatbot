# 현행 챗봇 · 팀원 PoC · Claude v7 — 3자 비교 (2026-10-15)

## 0. 전제
- 평가셋: 개발용 407 + 블라인드 1~6(1,420) = 1,827문항. 정답 집합 일치만 정답, 제한 메뉴는 '답변불가'로 통일.
- **팀원 PoC는 1·2단계(사전·오타)만 실행.** 3단계 임베딩 모델(KURE-v1)은 이 환경에서 내려받을 수 없음. "+유사도(추정)"은 3단계를 문자 TF-IDF(예시 질문 3,340)로 대체한 **상한 추정치**이며, 실제 KURE 결과는 이보다 높거나 낮을 수 있음.
- 팀원 PoC의 `data/KEYWORD_SET.csv`·`DOCUMENT_SET.csv`는 원본과 동일(2,568행·102행, 차이 없음). 목업 DB(10개 메뉴)는 쓰지 않고 실제 키워드 2,563개를 적재해 평가.
- 현행 챗봇은 2026-10-14 실측값. Claude는 "세트별 당시 버전"이 블라인드 값, v7은 블라인드6만 블라인드.

## 2. 세 시스템의 차이 (한 줄씩)
| 항목 | 현행 | 팀원 PoC | Claude v7 |
|---|---|---|---|
| 핵심 방식 | 형태소(Kiwi) 명사 → 키워드 완전일치, 아니면 **단어 임베딩 ≥0.89** | 공백 제거 후 **부분문자열 검색**(긴 것 우선) → 오타 → **문장 임베딩(KURE)** | 어절 경계 **사전 분할(DP)** → 오타 → 활용형·동의어 → **역할 슬롯** → 정리 → TF-IDF 유사도 |
| 띄어쓰기 | 형태소 분석이 흡수(44%) | 공백 제거로 해결(91%) | DP 분할(99%) |
| 동의어·구어체 | 단어 수준 임베딩이라 문맥 무시 | 사전이 하나라도 걸리면 임베딩을 **안 탐** → 구어체 26% | 사전 413개 + 규칙 44개 + 유사도 |
| 가해/피해 | 없음 | 없음 (키워드에 있을 때만) | 슬롯으로 판단, 역할반전 3건 |
| 복수 의도 | 여러 문서 가능하나 화면은 1개 | 부분문자열 전부 반환 → 수식어 과잉(예: "해 뜨기 전 시간대"→시간+도로형태) | 병렬 분리 + 수식어 제거 |
| 업무 밖 | 키워드 없으면 fallback | fallback/되묻기 구간 | 패턴 판정 + 안내 문구 |
| 모델 의존 | ko-sbert, Kiwi | KURE-v1/v2 (torch 필요) | 없음 (sklearn) |
| 응답 속도 | 사이트 실측 ~0.3초 | 규칙만 60~130ms(순수 파이썬 편집거리), 임베딩 포함 시 +모델 추론 | 5ms |

## 3. 팀원 PoC에서 바로 고칠 수 있는 것 (블라인드6 실패 117건 분석)
| 원인 | 건수 | 예 | 제안 |
|---|---:|---|---|
| 사전·오타 모두 실패 → fallback (임베딩 없이는 못 잡음) | 67 | 사고 핫스팟, 가구 수, 규정 속도보다 빨리 | 임베딩 단계 가동 + 동의어 사전(Claude thesaurus 463개 재사용 가능) |

| 수식어가 메뉴로 잡힘 (과잉 복수) | 10 | "기자인데요 작년 사망자 지역별로"→사망사고+시군구 | 약한 수식어 목록(지역별·연도별…) 제거 |
| 제한 메뉴 오판 | 9 | "무면어 운전 사고"(오타)→제한 메뉴로 보정 | 오타 보정 후보에서 제한 메뉴 제외, 제한 메뉴 안내 문구 분리 |

## 4. 권장
1. 두 안은 **경쟁이 아니라 결합**이 맞음: 팀원 PoC의 서비스 골격(FastAPI, DB 전환, 로그, /chat 호환) + Claude v7의 해석 규칙(어절 경계 분할·역할 슬롯·복수 분리·업무 밖·동의어 463)을 `matcher.py` 1·2단계 자리에 넣고, 3단계는 KURE 임베딩 유지.
2. KURE 모델이 있는 환경(팀원 PC)에서 같은 평가셋(`3_전체패키지/data/blind/*.csv`)으로 PoC 전체 파이프라인을 1회 측정해 "추정" 열을 실측으로 교체.
3. 결합 후에는 새 블라인드셋(또는 고정해 둔 평가용 180)으로 다시 1회 측정.
