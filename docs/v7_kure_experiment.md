# v7 + KURE 결합 실험 (2026-10-15)

## 1. 목적
PoC의 서버 골격(FastAPI, data_loader, `/chat` 응답 형식, 로그)은 유지하고, 해석 단계를 v7 엔진(규칙·사전·슬롯)으로 바꾼 뒤
**KURE 문장 임베딩을 붙이면 v7 단독보다 나아지는지** 확인한다.

## 2. 비교 대상
| 모드 (`CHATBOT_ENGINE`) | 동작 |
|---|---|
| `v7` | v7 엔진만. 규칙 → v7 자체 TF-IDF 유사도. KURE 모델 미사용 |
| `v7_kure_replace` | v7 규칙, TF-IDF를 끄고 그 자리를 KURE 임베딩으로 대체 (v7이 메뉴를 못 찾은 '미응답'일 때 KURE) |
| `v7_kure_fallback` | v7 규칙 + TF-IDF, 그래도 '해석 불가' 되묻기일 때만 KURE |

- v7 엔진 파일(`taas_nlu.py` 등)은 수정하지 않고 `v7_adapter.py`로 감싸서 사용. 기동 시 `SHA256.txt`와 해시를 대조해 동결본임을 확인.
- KURE 예시 질문: v7 예시 633 + AI 생성 2,707 = 3,340건. 생성 예시 중 '답변불가' 145건은 업무 밖 부류로 따로 표시하고, 임베딩 최상위가 이 부류면 fallback.
- 채점 기준: 안내 메뉴 집합 = 정답 집합, 제한 메뉴 18개는 '답변불가'로 통일 (시험 정답표와 같은 기준).

## 3. 방법
1. **재현 확인**: `v7` 모드로 blind6를 채점해 보고서 수치 88.8%가 나오는지 먼저 확인.
   data_loader 경로와 v7 `sources/` 사본 경로 모두 231/260, 문항별 차이 0건.
2. **임계값 조정 시도**
   - eval_dev(407)로만 조정하려 했으나, v7이 eval_dev에서 99.5%(표본 내)라 KURE까지 가는 문항이 replace 2개, fallback 0개로 조정 불가.
   - blind1~5에서도 KURE 도달 문항이 replace 40개 / fallback 5개로, 사전에 정한 기준(50개) 미만이라 조정값(설정 B)은 만들지 않음.
3. **임계값 고정**: 설정 A = PoC 기본값 (답변 0.75 / 되묻기 0.60 / 1·2등 차이 0.03)을 `taas_chatbot_poc/v7k_thresholds.json`에 고정하고
   **커밋 `5a75b25`** 후에 blind6를 열어 봄.
4. **1회 채점**: 커밋 `5a75b25` 상태에서 blind6(260문항)를 모드별로 1회만 채점.
   - `5a75b25`에는 평가셋·비교 엑셀이 함께 들어 있어 공개 저장소에는 올리지 않고 로컬 태그 `blind6-freeze`로만 보존한다.
   - 공개 이력의 **`6ae295a`는 같은 코드·같은 임계값에서 평가 데이터 파일만 뺀 커밋**이다 (`git diff blind6-freeze 6ae295a -- taas_chatbot_poc` 결과 없음).
5. 판단 기준(사전 합의): v7 단독과 차이가 3%p 미만이면 "KURE 효과 없음".

## 6. 결론
- **KURE 효과 없음.** 두 변형 모두 v7 단독 대비 +0.4%p(1문항)로 기준(3%p)에 크게 못 미친다.
- **이유: 남은 오답이 v7의 '확신 오답'이라 fallback 구조로는 고칠 수 없다.**
  v7 단독 오답 29건 중 28건은 v7이 메뉴를 확정해 답한 경우(사전 18, 유사도 4, 슬롯 4, 복수 2)이고, 되묻기는 1건뿐이다.
  KURE는 v7이 "모르겠다"고 할 때만 개입하므로 이 28건에는 닿지 않는다.
- replace 변형은 맞게·틀리게 바뀐 문항이 엇갈려 순증가가 1건이고, P95 응답시간이 v7 단독의 3배 이상이다.
- 따라서 **기본 엔진은 `v7`**. KURE 두 변형은 코드에 옵션으로 남겨 둔다.

## 7. 한계
- 시험 질문·정답표는 AI(Claude)가 작성했고, 정답표는 담당자 검수 전이다.
- v7 예시 질문과 blind6 사이에 같은 문장 16건이 있어 '중복 제외' 수치를 함께 적었다.
- 바뀐 문항이 1~9건 수준이라 두 변형 간 차이는 통계적으로 의미가 없다.
- 설정 A는 데이터로 조정하지 않은 값이다 (조정에 쓸 KURE 도달 문항이 부족).

## 8. 실제 로그를 받으면 다시 볼 조건
아래 중 하나라도 해당하면 같은 절차(임계값 고정 → 커밋 → 1회 채점)로 다시 측정한다.
1. **v7 미해석 비율이 높을 때**: 실제 로그에서 v7이 되묻기·미응답으로 끝나는 질문이 5% 이상이면 KURE가 개입할 여지가 생긴다.
2. **조정 표본이 충분할 때**: 정답을 붙인 실제 질문 중 KURE까지 가는 문항이 50개 이상이면 설정 B(임계값 조정)를 만든다.
3. **확신 오답을 다룰 구조로 바꿀 때**: v7이 답을 확정한 경우에도 KURE 점수를 함께 보고 둘이 다르면 되묻는 '교차 확인' 방식을 검토한다.
   이번 실험의 fallback 구조와는 다른 실험이므로 새 평가셋으로 측정한다.
4. **v7 규칙이나 사전이 바뀔 때**: 동결 해시가 달라지면 v7 단독 기준 수치부터 다시 잰다.

## 9. 재현 방법
```bash
cd taas_chatbot_poc
python import_data.py            # data/의 원본 CSV·엑셀 → taas.db, data/eval/*.csv
CHATBOT_ENGINE=v7 uvicorn app:app --port 8000
python evaluate.py --url http://127.0.0.1:8000/chat --eval data/eval/블라인드6.csv --out result_v7_blind6.csv
```
KURE 변형은 `CHATBOT_ENGINE=v7_kure_replace` 또는 `v7_kure_fallback` (KURE 모델 필요, 예시 임베딩에 기동 약 3분).
원본 데이터와 평가셋은 공개 저장소에 올리지 않으므로 별도로 받아 `taas_chatbot_poc/data/`에 둔다.
